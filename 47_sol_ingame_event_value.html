인게임 이벤트 채널 실측 — 신작 런칭 참고

솔리테어 시티 저니 · 페이스북 인스턴트 게임 · 실측 구간 2026-07-20 ~ 08-08 · 작성 08-11

요약
  • 런칭 부스팅 물량에 취하면 안 됨 — 물량은 압도적이지만 D1은 5.9%로 전 채널 최저임.
  • 부스팅이 끝나면 남는 건 일 68명 수준 — 런칭 계획을 이 숫자 기준으로 세워야 함.
  • 인게임 이벤트는 작지만 D1이 부스팅의 3배 — 발행 중 하루 12.8명(피크 25.7명), 자연 유입의 19%.
  • 결론 — 만들 값어치는 있음. 단 조건이 붙음. 아트 약 2주로 3.5개월치 채널이 생기지만, 런칭 전에 · 인게임 캡처 기반으로 · 한 번에 만들어야 성립함. 크로스프로모 슬롯이 남아 있다면 그쪽이 29배 효율이라 순위가 밀림.

1. 런칭 부스팅의 실체

New Game Featuring 기간에는 인게임 메뉴로 유입이 몰림. 신규의 절대다수를 차지하지만 D1이 5.9%로 가장 낮음. 이 구간의 DAU를 제품 성과로 읽으면 종료 후 판단이 어긋남.

피할 것 — 부스팅 기간 유입량을 기준선으로 잡고 리텐션 목표를 세우는 것. 채널 믹스가 통째로 바뀌므로 전후 지표를 직접 비교할 수 없음.

2. 부스팅이 끝나면 남는 것

웹게임허브 순수 41.9명 + 게이밍탭 26.5명 = 일 68.4명. 이 규모에서는 하루 10명대 채널도 무시할 수 없는 비중이 됨.

할 것 — 런칭 초기부터 "부스팅 제외 자연 유입"을 따로 집계해 두기. 종료 시점에 급하게 만들면 비교 기준선이 없음.

질은 D1까지만 우위가 확인됨 — 인게임 이벤트 D1 10.3~22.4% 대 부스팅 5.9%. 다만 D7·D14는 이벤트별 표본이 49~112명이라 판정할 수 없음(부록 A 참조). 자연 유입 전체를 이기는 것도 아님 — 웹게임허브 순수가 34.6%로 더 높음.

즉 성장 레버가 아니라 보조 채널임. 유입 규모를 키우는 것이 목적이라면 크로스프로모가 같은 기간 6,314명으로 이벤트의 29배임.

4. 판정 — 런칭 전에 재고를 만들 값어치가 있는가

들어간 비용 (솔리테어 실제)

  • 배너 7종 × 2규격 = 14장. 아트 1명이 다른 업무와 병행해 약 2주에 걸쳐 순차 제작(2026-07-16 요청 → 07월 말 완료).
  • 기획 쪽은 Event Info 문구 7세트(이름·짧은 설명·긴 설명, 영문 글자수 제한 검증)와 편성 캘린더.
  • 리젝 1회로 재작업 발생 — 배너에 팝업 UI를 그려 넣었더니 "인게임에서 해당 이벤트를 확인할 수 없다"로 반려됨.

나온 산출

  • 이벤트 1건당 약 73명 → 7종이면 약 511명, 월 2회 편성으로 3.5개월치 채널.
  • 부스팅 종료 후 자연 유입(일 68명) 기준으로 발행 기간 중 +19%, 피크일 +38%.
  • D1은 부스팅의 3배 수준. 단 D7 이후는 표본 부족으로 판정 불가.

판정

만들 값어치는 있음. 아트 2주로 3.5개월 굴러가는 채널이 생기고, 부스팅이 빠진 뒤에는 이 정도 증분도 비중이 큼. 다만 조건 없이 권장할 수는 없음 — 아래 셋이 갖춰져야 성립함.

1. 런칭 전에 끝내 둘 것. 콜드스타트는 30일인데 제작에 2주가 듦. 런칭 후 시작하면 절반을 흘려보냄. 솔리테어도 이미 1주가 지난 뒤에 착수해 초반 구좌를 놓쳤음.
2. 인게임 캡처 기반으로 만들 것. 심사는 배너를 실제 게임 화면과 대조함. 새로 그린 연출이 들어가면 반려됨. 창작이 아니라 캡처 + 문구 조합으로 접근하면 공수도 리젝 위험도 함께 내려감.
3. 종류를 한 번에 묶어 요청할 것. 반복 신청은 반려되므로 준비한 종류 수 = 쓸 수 있는 개월 수임. 낱개로 그때그때 요청하면 매번 아트를 부르게 되고, 그 구조에서는 건당 73명이 공수를 정당화하지 못함.
먼저 따져볼 것 — 크로스프로모 슬롯이 남아 있는가. 같은 기간 크로스프로모 유입이 6,314명으로 인게임 이벤트의 29배임. 형제 게임이 있고 슬롯이 비어 있다면 아트 공수는 그쪽이 먼저임. 인게임 이벤트는 크로스 슬롯이 없거나 이미 찼을 때의 차선책으로 보는 것이 맞음.

운영 규칙

  • 게임당 월 상한 = 별도 이벤트 2개, 또는 최대 2주짜리 1개. 초과는 파트너 사전 상담이 필요함.
  • 사용 가능한 유형은 2종 — 리더보드 계열(COMPETITION), 컬렉션 계열(CHALLENGE).
  • Event name은 게임 안 타이틀과 일치시켜야 함(심사가 인게임 화면과 대조함).
  • 상시 콘텐츠(리더보드·컬렉션·출석)도 이벤트 형태로 제출해 구좌를 확보할 수 있음.

계측 — 이벤트 유입이 자연 유입에 섞임

이벤트로 들어온 유저도 entrypoint_join.entry가 web_games_hub로 찍히고 payload.social로만 구분됨. 분리하지 않으면 웹게임허브 성과가 부풀려짐. 이 문서의 수치는 분리한 값임.

할 것 — 런칭 시점에 payload 기준 세그먼트를 대시보드에 미리 심어 두기.
