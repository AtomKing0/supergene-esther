지표가 무너지는 게 아니라 유입 구성이 통째로 바뀐 것. 런칭 초기 고품질 Meta 피처링 파도가 식고, Meta가 알고리즘으로 배포하는 '인게임 메뉴'(D1 최저·우리 컨트롤 밖) 물량이 최근 유입의 과반을 차지하며 블렌디드 리텐션을 희석. 볼륨은 오히려 늘었음.
  • 블렌디드 D1 전체 7.4% → 최근 4.6% 로 하락. 원인은 게임/코호트 품질 저하가 아니라 믹스 이동.
  • Meta 인게임메뉴(FBS 상 in_game_menu 중 CROSS_ 없는 순수 Meta 배포) = 최근 유입의 3.0%·D1 최저. 우리가 켜거나 끌 수 없음 — Meta가 자체 알고리즘으로 솔리테어를 플랫폼 메뉴에 노출(7/19 크게 열림, 아래 일별 표).
  • 우리가 직접 컨트롤하는 채널은 건강 — 자체 크로스프로모(CROSS_ payload·D1 14%)·Meta 디스커버리(web_games_hub 등)는 D1 상위. 게임 자체 문제 아님. 크로스프로모는 Meta 인게임메뉴와 별개(CROSS_ 마킹으로 식별·우리가 직접 운영).
  • 레버 3 — ①지표를 세그로 분리 보고(블렌디드는 Meta 배포량에 좌우) ②Meta 인게임메뉴 저의도 유저 전환은 로딩·FTUE·첫세션이 유일 레버(#371 로딩·에셋 최적화 직결).

유입 분류(FBS): Meta = Facebook이 알고리즘으로 배포(우리 컨트롤 밖) · 자체 = 우리가 직접 운영(크로스프로모·공유·봇) · 직접 = 유저 자발적 재진입(bookmark·home_screen_shortcut·빈값 SOLO·other, 우리·Meta 컨트롤 밖·충성 신호). ★payload.social=CROSS_* = 자체 크로스프로모 — 지면(entry)이 뭐든 우리 것이며 Meta 인게임메뉴에 포함되지 않음. Meta 인게임메뉴 = CROSS_ 없는 순수 in_game_menu(Meta 알고리즘 추천). game_switch도 우리 스위처.

세부 엔트리포인트별 D1 🌐 전체 기준정식~어제 코호트 · 순수 진입 지면 단위 · CROSS_(자체 CP)는 아래 CP 표에서 별도

FBS 진입 지면만 표시(CROSS_ 자체 CP·entry 미기록(빈값)은 제외 — 빈값=SOLO 직접/복귀로 FBS 진입점 아님). 순수 in_game_menu(Meta 알고리즘 추천)가 최저의도(D1 최저) — 7/19 급증한 그 지면. web_games_hub·facebook_web 같은 Meta 디스커버리는 상위권.

STEP 5 · 레버
그럼 우리가 돌릴 수 있는 건 — 자체 채널 두 개
Meta 물량은 컨트롤 밖이므로, 직접 켜고 끌 수 있는 CP 소스와 인게임 이벤트 알림의 효율만 따로 본다.

우리 CP(CROSS) 소스별 효율 🌐 전체 기준CP 크리에이티브 대상 자사 게임별 · 정식~어제 코호트

지면: switch=우리 게임 스위처 버튼(entry=game_switch) / menu=우리 CP가 뜨는 인게임 메뉴 슬롯(entry=in_game_menu + payload.social=CROSS_*). 둘 다 우리가 켜고 끄는 자리이며 Meta 알고리즘 지면이 아님 — 같은 in_game_menu라도 CROSS_ 태그가 없는 것만 Meta 인게임메뉴로 분류함. 같은 소스도 switch 쪽 D1이 높음.

인게임 이벤트 알림 페이로드별 성과 · 발행상태 🌐 전체 기준payload.social=ingame_event_* · 재참여 알림(기존 유저 대상) · 발행중/완료/대기는 일별 클릭 로그 실측 판정

CROSS_(자체 CP=신규유입)와 달리 인게임 이벤트 알림은 기존 유저 재참여 목적이라 지표를 경유 진입 유저 수(클릭)+D1 복귀로 봄. 발행상태는 일별 로그 실측으로 판정(활성 푸시창 끝이 어제/오늘=🔴발행중, 지났으면=✅완료, 로그0=⏸대기). 대기 페이로드는 추적 세팅 완료, 발행 시작하면 자동 집계.
