돈이 없어 못 놀던 유저를 들여보내면 무엇을 얻는가

무료 입장 1판이 우리에게 돌려주는 것을 판수·리텐션·광고·비용 네 축으로 실측함. 전 구간 서구권(NA+EU)·내부 인원 제외.

배포 전 2026-08-01~08-10 배포 후 08-12~08-13 소스 raw.solitaire_city_journey
무료 1판은 그날의 활동량을 만든다 — 다만 다음날 복귀는 아니다

막혀 있던 유저가 무료로 한 판 들어가면 그 한 판에서 끝나지 않고 평균 8.06판을 하고 광고를 약 8회 본다. 클리어율 97%에 보상이 입장료의 3.3~5.6배라 한 판 이기면 다음 판 밑천이 생기기 때문임. 절반 가까이(47.9%)가 사흘 이상 계속 쓴다. 면제하는 건 골드라 실물 매출 잠식은 0. 다만 다음날 복귀율은 대조군과 차이가 없음(46.6~51.3% vs 47.3%, p=0.23~0.87) — 이 기능의 값어치는 리텐션이 아니라 활동량과 광고 노출로 주장해야 함.

① 리텐션 — 확증 실패 8/18 정정

초판(8/14)의 +17.5%p는 표본 54건짜리였고, 600건으로 늘리자 사라짐 배포 첫날 코호트만으로 D1 64.8%가 나와 리텐션 상승으로 결론냈으나, 5일치(600 유저-일)로 다시 재니 51.3%, 첫 수령 코호트 기준으로는 46.6%로 대조군(47.3%)과 사실상 같음. 초판 결론을 철회함.

배포 전 "회복해서 플레이"(광고를 봐서라도 들어간 층)의 66.3%와도 크게 벌어짐. 그 그룹은 동기가 강한 자기선택 집단이었고, 무료로 그냥 들어온 유저는 그 층이 아니었음 — 초판에서 "상한으로 봐야 한다"고 단 경고가 맞았던 것.

리텐션이 떨어지지도 않았음 두 비교 모두 신뢰구간이 0을 걸침(−9.1~+10.7%p). "올랐다"도 "내렸다"도 아님. 가드레일 관점에서는 통과이고, 성과 주장 근거로는 쓸 수 없음.

② 깊이 — 왜 1판에서 안 끝나는가

무료 판 클리어율이 97%이고 판당 보상이 입장료의 3.3~5.6배임. 한 판 이기면 그 골드로 다음 판을 사고, 그게 다시 보상을 낳음. 무료 입장은 골드를 주는 게 아니라 골드를 벌 기회를 여는 것임.

그리고 한 번 쓰고 마는 기능이 아님 — 첫 수령 코호트 219명이 평균 2.69일 무료 입장을 썼고, 47.9%가 사흘 이상 사용함. 판수 밴드는 그대로 리텐션 밴드임 — 배포 전 실측 D1은 1판 18.5% · 2~3판 29.9% · 4~9판 40.4% · 10판+ 58.0%. 잔고 부족 유저의 절반(50.9%)이 4판 이상으로 올라감.

정리하면 실물 비용 없이 판수·광고 노출·리텐션을 사는 구조임. 다만 골드 IAP를 붙이는 시점에는 이 계산이 달라지므로, 그때 면제 규모를 재검토해야 함.

해석 주의

  • 초판(8/14) 리텐션 결론은 철회됨 — n=54에서 나온 +17.5%p가 n=600에서 사라짐. 배포 초기 며칠의 소표본으로 성과를 결론내지 말 것이 이번 건의 교훈임.
  • 배포 전 B군(회복해서 플레이)은 자기선택 집단임 — 광고를 봐서라도 들어간 유저라 동기가 높음. 무료 입장 유저는 그 층이 아니므로 66.3%를 기대치로 쓰면 안 됨.
  • 판당 광고 매출은 추정치임 — ARPDAU를 판수로 나눈 값이라 지면별 eCPM 차이를 반영하지 못함. 규모 감각용으로만 쓸 것.
  • 0판 유저-일 전체와 비교하면 안 됨 — 전체 0판의 D1은 36.7%인데 여기엔 잠깐 접속만 한 코어 유저가 섞여 있음. 반드시 잔고 부족 조건으로 걸러야 함.

쿼리

전부 country IN (서구권) · country != 'KR'(내부 인원) 조건이 붙어 있음. 서구권 목록은 supergene-common.analytics_common.tb_dim_country의 Europe + US·CA임.

① 배포 전 — 돈이 없던 유저-일의 D1 (0판 vs 회복 플레이) 
WITH src AS (
  SELECT player_id, log_date, log_time, event, data
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date BETWEEN '2026-07-28' AND '2026-08-11'   -- 잔고 추적용으로 앞을 넉넉히 잡음
    AND country IN (<서구권>)),
-- 레벨별 x1 입장료 = 그 레벨 entry_cost의 최소값
lv AS (SELECT lv, MIN(ec) x1 FROM (
    SELECT SAFE_CAST(JSON_VALUE(data,'$.user_level') AS INT64) lv,
           SAFE_CAST(JSON_VALUE(data,'$.entry_cost') AS INT64) ec
    FROM src WHERE event='2100_GAMEPLAY_START') WHERE ec>0 GROUP BY lv),
ud AS (SELECT player_id, log_date, MIN(log_time) t0,
         COUNTIF(event='2100_GAMEPLAY_START') plays
       FROM src GROUP BY 1,2 HAVING COUNTIF(event='1000_LOGIN_COMPLETE')>0),
gold AS (SELECT player_id, log_time, SAFE_CAST(JSON_VALUE(data,'$.after') AS INT64) bal
         FROM src WHERE event='9400_GOLD_TRANSACTION_LOG'),
lvl AS (SELECT player_id, log_time, SAFE_CAST(JSON_VALUE(data,'$.user_level') AS INT64) l
        FROM src WHERE event='2100_GAMEPLAY_START'),
-- 그날 첫 로그인 직전의 잔고 = 세션에 들고 온 돈
j AS (SELECT u.player_id, u.log_date, u.plays,
        ARRAY_AGG(g.bal ORDER BY g.log_time DESC LIMIT 1)[SAFE_OFFSET(0)] bal
      FROM ud u LEFT JOIN gold g
        ON g.player_id=u.player_id AND g.log_time < u.t0
      GROUP BY 1,2,3),
k AS (SELECT j.*, ARRAY_AGG(l.l ORDER BY l.log_time DESC LIMIT 1)[SAFE_OFFSET(0)] lev
      FROM j LEFT JOIN lvl l
        ON l.player_id=j.player_id AND l.log_time < DATETIME(j.log_date)
      GROUP BY 1,2,3,4),
-- 핵심 필터: 세션 시작 시점에 잔고 < x1 입장료
broke AS (SELECT k.*, lv.x1 FROM k JOIN lv ON lv.lv = k.lev
          WHERE k.bal IS NOT NULL AND k.bal < lv.x1
            AND k.log_date BETWEEN '2026-08-01' AND '2026-08-10'),
nxt AS (SELECT DISTINCT player_id, log_date FROM ud)
SELECT IF(b.plays=0,'A. 못 들어감(0판)','B. 회복해서 플레이(1판+)') grp,
  COUNT(*) user_days, ROUND(AVG(b.plays),2) avg_plays,
  ROUND(100*COUNTIF(n.player_id IS NOT NULL)/COUNT(*),1) d1_pct
FROM broke b LEFT JOIN nxt n
  ON n.player_id=b.player_id AND n.log_date=DATE_ADD(b.log_date, INTERVAL 1 DAY)
GROUP BY 1;
-- 결과: A 347유저-일 47.3% / B 789유저-일 66.3%  (+19.0%p, z=6.04, p<0.001)
② 배포 후 — 무료 입장 수령자의 D1 
WITH fe AS (   -- 2098 페이로드로 '무료 아니면 못 들어갔을' 유저 판별
  SELECT player_id, log_date,
    MAX(IF(SAFE_CAST(JSON_VALUE(data,'$.gold_balance') AS INT64)
         < SAFE_CAST(JSON_VALUE(data,'$.entry_cost')  AS INT64),1,0)) broke
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date BETWEEN '2026-08-12' AND '2026-08-17'   -- 완결일 전 구간(초판은 8/12 하루만 썼다가 정정)
    AND event='2098_DAILY_FREE_ENTRY' AND country IN (<서구권>)
  GROUP BY 1,2),
ud AS (SELECT player_id, log_date, COUNTIF(event='2100_GAMEPLAY_START') plays
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date BETWEEN '2026-08-12' AND '2026-08-18' AND country IN (<서구권>)
  GROUP BY 1,2 HAVING COUNTIF(event='1000_LOGIN_COMPLETE')>0),
nxt AS (SELECT DISTINCT player_id, log_date FROM ud)
SELECT IF(f.broke=1,'무료 입장 · 잔고 부족','무료 입장 · 잔고 충분') grp,
  COUNT(*) user_days, ROUND(AVG(u.plays),2) avg_plays,
  ROUND(100*COUNTIF(n.player_id IS NOT NULL)/COUNT(*),1) d1_pct
FROM fe f JOIN ud u USING (player_id, log_date)
LEFT JOIN nxt n ON n.player_id=f.player_id
  AND n.log_date=DATE_ADD(f.log_date, INTERVAL 1 DAY)
GROUP BY 1;
-- 결과(8/18 재측정): 잔고부족 600유저-일 8.06판 D1 51.3% / 잔고충분 1,758유저-일 21.22판 53.8%
-- ★ 초판(8/12 하루, n=54)에서는 64.8%가 나왔으나 표본이 커지자 51.3%로 내려앉음 → 리텐션 결론 철회
-- ★ 첫 수령 코호트(219명) 기준 D1은 46.6%로 대조군 47.3%과 사실상 동일(p=0.873)
③ 깊이 — 무료 입장 수령자가 그날 몇 판까지 가는가 
WITH fe AS (
  SELECT player_id, log_date,
    MAX(IF(SAFE_CAST(JSON_VALUE(data,'$.gold_balance') AS INT64)
         < SAFE_CAST(JSON_VALUE(data,'$.entry_cost')  AS INT64),1,0)) broke
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date >= '2026-08-12' AND event='2098_DAILY_FREE_ENTRY'
    AND country IN (<서구권>) GROUP BY 1,2),
ud AS (SELECT player_id, log_date, COUNTIF(event='2100_GAMEPLAY_START') p
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date >= '2026-08-12' AND country IN (<서구권>) GROUP BY 1,2)
SELECT IF(broke=1,'잔고 부족','잔고 충분') grp,
  COUNT(*) user_days, ROUND(AVG(p),2) avg_plays,
  APPROX_QUANTILES(p,100)[OFFSET(50)] p50,
  ROUND(100*COUNTIF(p=1)/COUNT(*),1)  only1_pct,
  ROUND(100*COUNTIF(p>=4)/COUNT(*),1) deep4_pct,
  ROUND(100*COUNTIF(p>=10)/COUNT(*),1) deep10_pct
FROM fe JOIN ud USING (player_id, log_date) GROUP BY 1;
④ 판수 밴드별 D1 · 광고 노출 전후 
-- 판수 밴드별 D1 (배포 전, 서구권)
WITH ud AS (
  SELECT player_id, log_date, COUNTIF(event='2100_GAMEPLAY_START') p
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date BETWEEN '2026-08-01' AND '2026-08-11' AND country IN (<서구권>)
  GROUP BY 1,2 HAVING COUNTIF(event='1000_LOGIN_COMPLETE')>0),
nxt AS (SELECT DISTINCT player_id, log_date FROM ud)
SELECT CASE WHEN p=0 THEN '0판' WHEN p=1 THEN '1판' WHEN p<=3 THEN '2~3판'
            WHEN p<=9 THEN '4~9판' ELSE '10판+' END band,
  COUNT(*) user_days,
  ROUND(100*COUNTIF(n.player_id IS NOT NULL)/COUNT(*),1) d1_pct
FROM ud a LEFT JOIN nxt n
  ON n.player_id=a.player_id AND n.log_date=DATE_ADD(a.log_date, INTERVAL 1 DAY)
WHERE a.log_date <= '2026-08-10' GROUP BY band;
-- 결과: 0판 36.7% / 1판 18.5% / 2~3판 29.9% / 4~9판 40.4% / 10판+ 58.0%

-- 유저-일당 광고 노출 전후 (8/12 롤아웃 중간일 제외)
WITH ud AS (
  SELECT player_id, log_date,
    COUNTIF(event='2100_GAMEPLAY_START')          plays,
    COUNTIF(event='4210_RV_FINISH')               rv,
    COUNTIF(event='4010_INTERSTITIAL_AD_FINISH')  it
  FROM `game-log-359704.raw.solitaire_city_journey`
  WHERE log_date BETWEEN '2026-08-05' AND '2026-08-13' AND country IN (<서구권>)
  GROUP BY 1,2 HAVING COUNTIF(event='1000_LOGIN_COMPLETE')>0)
SELECT IF(log_date<='2026-08-11','배포 전','배포 후') grp, COUNT(*) user_days,
  ROUND(AVG(plays),2) plays_pu, ROUND(AVG(rv),2) rv_pu, ROUND(AVG(it),2) it_pu
FROM ud WHERE log_date != '2026-08-12' GROUP BY 1;
-- 결과: 판수 11.87→13.14 / RV 4.10→4.31 / IT 2.82→7.28
-- ★ IT 급증은 전면광고 빈도(SPEC-035) 변경이 섞인 값이라 이 기능의 성과로 읽지 말 것
