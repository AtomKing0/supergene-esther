밸런스시트 기획서의 역할

무슨 값을 어디에 적고, 바꾸면 무엇이 달라지는지 확인하는 문서다. 표의 목적 → 조절 영향 → 컬럼 뜻·단위·허용값 순으로 읽는다. 계산 예시는 단가·확률·수급을 이해하기 위한 것이다.

기능의 실행 순서, 후보 비교, 실패 처리, 저장 상태와 통신은 개발 기획서에서 정의한다. ★ 구현 약속은 해당 문서 링크로 안내한다. 실제 값은 밸런스시트가 관리하며, 문장 정리와 플레이 밸런스 검증 완료는 구분한다.

1. 시트 공통 사용법

표와 JSON의 관계

시트 한 탭이 클라이언트 JSON 파일 하나에 대응한다. Row1은 사람이 읽는 설명, Row2는 JSON 필드 이름, Row3부터는 데이터다. 헤더 없는 빈 열을 기준으로 왼쪽은 클라이언트 데이터, 오른쪽은 기획 검수용 설명이다.

이름과 식별 번호

새 필드 이름은 소문자와 언더바를 사용한다. 기존 호환 형식의 필드명은 각 표의 실제 스키마를 따른다. 문구 키의 값은 T_STRING_CODE 형식이며 string_code의 식별 컬럼은 Key다. 일반 표의 key_number = band × 10000 + 순번은 최초 발급 뒤 유지한다. 행을 정렬하거나 삭제해도 기존 번호를 당기거나 재사용하지 않는다.

단위와 빈 값

시간은 기본적으로 초(_sec)다. 진동 길이처럼 명시된 _ms는 밀리초다. 금액·개수·기간은 각 컬럼의 단위를 따른다. none·0은 각 필드에 정의된 의미로 사용한다. 0을 모두 미정·무제한·꺼짐으로 처리하면 안 된다. 미확정 필드는 설명에 별도로 표시한다.

확률과 가중치 계산

  • 확률: 10000이 100%다. 예: 2500은 25%.
  • 정규화 가중치: 같은 그룹의 합을 10000으로 맞춘다. 후보 일부를 제외했다면 남은 가중치 합으로 나눠 추첨한다.
  • 생산 내용물 가중치: 주머니 초기 구성의 개수다. 합은 주머니 한 바퀴의 길이이므로 10000으로 바꾸지 않는다. 소진·재충전 처리는 개발 기획서를 따른다.

참조·보상·활성 상태

다른 표를 참조하는 키는 실제 대상 행이 있어야 한다. 보상은 아이템 키와 수량을 한 쌍으로 읽고 값이 있는 쌍을 모두 처리한다. in_use가 있는 표는 활성 행만 사용한다. 이 컬럼이 없는 호환 표는 각 표의 설명을 따른다.

수정 후 확인

기획자가 시트를 수정하면 변경분을 클라이언트 JSON과 문서에 반영한다. 키·참조·단위·가중치·보상 누락을 검사한 뒤 배포한다. 보상·진행 속도를 바꾼 경우에는 같은 플레이 조건으로 수급과 소요 시간을 다시 확인한다. 데이터 검사 통과만으로 플레이 밸런스가 검증된 것은 아니다.

1-12. 시트가 실수를 막는 장치

FK 칸을 하늘색으로 칠하는 것만으로는 오타가 막히지 않는다. 적재 스크립트가 시트에 직접 드롭다운과 주석을 건다.

장치범위하는 일
엄격 드롭다운63칸불리언은 체크박스, 보상 칸과 FK 는 목록 밖 값을 막는다. 짧은 enum 은 경고만 띄운다. 값이 전부 다른 식별자 칸에는 걸지 않는다
헤더 셀 주석335칸Row2 셀에 그 칸의 뜻·규칙·타입·근거가 주석으로 붙는다. 내용은 _schema.json 에서 그대로 태우므로 손으로 다시 적지 않는다
Row1 A열에 표 이름45탭PMM_{테이블명} 을 적는다. 탭을 복사해도 A1 이 원본 표를 말해 준다

1-13. 보상은 이렇게 적는다

보상 칸에는 접두형 문자열 키 한 개만 넣는다. 「종류」 칸을 따로 두지 않는다 — 접두가 곧 종류다.

  • 보상 칸의 값은 언제나 currency_gem · item_2501 같은 접두형 키 하나다. 접두를 보면 재화인지 아이템인지 바로 읽힌다.
  • 열 이름도 여덟 탭이 같다 — reward_item_key 하나다.
  • 범주 칸(reward_type)을 따로 두면 한 열에 범주와 값이 섞인다. 그래서 두지 않는다.
규칙내용
1보상 칸의 값은 reward_key.reward_key 의 접두형 문자열 키뿐이다 — currency_*(7) · booster_*(2) · item_*(238) · 빈 슬롯 "none". 정수 아이템 코드를 보상 칸에 넣지 않는다
2열 이름은 reward_item_key(단일) · reward_item_key_N(다중)과 짝인 reward_amount · reward_amount_N 하나뿐이다. 예외 하나 — product 는 reward_type 이라는 이름을 쓴다. 담기는 값은 위 규칙과 똑같다
3「종류」 칸을 따로 두지 않는다. 접두가 곧 종류다
4보드 아이템 그래프(item_spec.item_code · produce_item_N · generator_N)는 정수 그대로다. 클라가 쓰는 아이템 id 이고 보상 이름공간과 다른 축이다. 두 이름공간을 잇는 자리는 reward_key.item_code 한 칸뿐이다
5시즌 패스 토큰 적립량은 보상 슬롯이 아니다. token_amount 라는 다른 이름을 쓴다

검사는 이름 규칙으로 전 표를 훑어 979칸을 reward_key 에 대조한다(빌드가 센다). reward_item_key 라는 이름을 쓰면 저절로 검사에 든다. 시트에서는 reward_key 250행짜리 엄격 드롭다운이 목록 밖 값을 막는다.

1-14. 비슷해 보이는 값의 주인

이름이 닮은 칸이 여럿 있다. 주인이 어느 표인지를 여기서 정한다. 같은 숫자를 두 곳에 적지 않는다.

1-15. 무엇이 얼마나 나오는지 보여 준다

생성기와 상자를 누르면 무엇이 얼마나 나오는지를 상세 팝업에 적는다. 다만 확률 컬럼은 만들지 않는다 — 표시할 값은 개수에서 계산한다.

  • produce_weight_N 은 확률이 아니라 생성기 안에 든 개수다(§1-7). 확률 컬럼을 따로 붙이면 같은 숫자가 두 곳에 앉는다.

1. 값의 용도와 조절 영향

이 표에서 관리하는 값

보드 아이템의 합치기·생산·판매 규칙

  • item_code로 아이템 한 행을 찾는다. merged_item_code는 다음 머지 결과, spread_*는 생산 비용·재고·회복 시간, produce_*는 산출 구성이다.

조절할 때 확인할 영향

에너지 비용을 올리면 같은 생산량에 더 많은 에너지가 필요하다. 재고 상한은 연속 생산량, 회복 초는 대기 길이를 바꾼다. produce_weight_N의 합은 주머니 한 바퀴의 개수다. 원작 고정 생성기 수치는 임의 조절하지 않는다.

2. 컬럼 설명

  • key_number : 이 행의 일련 번호. band×10000+순번 이고 시트 전체에서 유일하다 (현재 표 값 40001~40238)정수
  • item_code : 아이템 자연키. 머지 축의 정의원이고 다른 표는 전부 이 값을 참조한다 (현재 표 값 101~3202)정수
  • merged_item_code : 이 아이템 둘을 합쳤을 때 나오는 다음 단계 코드 (정수 코드 또는 재화 리터럴 · → item_spec.item_code · "none" = 마지막 단계 · 현재 표 값 208종)정수 또는 문자
  • rare : 희귀도 등급 (값 미확정 — 임시 값이므로 구현 전 확인 · 현재 표 값 전 행 0)정수
  • selling_price : 이 아이템을 팔았을 때 받는 코인이다. 상점 가격이 아니다 (0 = 판매 불가 · 현재 표 값 0~12)정수
  • protect_level : 보호 단계. 값이 있으면 실수로 팔거나 지우는 것을 막는다 (값 미확정 — 임시 값이므로 구현 전 확인 · 현재 표 값 전 행 0)정수
  • level_up_piece : 이 아이템이 레벨업 부품으로 쓰일 때의 대상 코드 (값 미확정 — 임시 값이므로 구현 전 확인 · 현재 표 값 전 행 0)정수
  • level_down_piece : 레벨다운 부품 대상 코드 (값 미확정 — 임시 값이므로 구현 전 확인 · 현재 표 값 전 행 0)정수
  • spread_auto : 탭을 받지 않고 스스로 내놓는 생성기인가. 참이면 에너지를 쓰지 않고 재고가 남아 있는 동안 타이머로 산출한다 (현재 표 값 true 5 / false 233)참/거짓
  • spread_weight_type : 어떻게 뽑는가. 1 = 다 나오면 다시 채워진다 · 2 = 한 번만 나온다(다시 채우지 않는다) · 3~5 = 오더 연동 상자(오더가 모자란 것을 그대로 준다) (값 미확정 — 임시 값이므로 구현 전 확인 · 현재 표 값 0~2)정수
  • spread_item_max : 보드에 얹힌 생성기가 쥐고 있는 재고 상한. 탭 한 번에 1 씩 줄어든다 (0 = 생성기가 아님 · 현재 표 값 0~80)정수
  • spread_storage_max : 그 생성기의 창고 상한. 보드 재고가 비면 여기서 채운다 (0 = 생성기가 아님 · 현재 표 값 0~240)정수
  • spread_cost_energy : 탭 한 번에 쓰는 에너지 (현재 표 값 0~1)정수
