Super Hard 물량이 50% 늘고 증가분이 상위 밴드에서 온다고 잡은 값임. 구성 변화만으로 기대 효과보다 크게 움직임. 실패율은 효과를 과대평가하게 되고, 잔여는 방향이 반대라 효과를 지워버림.

그래서 판정 지표는 실패율을 유지하되, 반드시 표준화해서 읽음. 잔여로 바꾸는 건 더 나쁨.

참고 — 하루 단위로 이만큼 흔들림

패치 전 18일간 Super Hard 일별 실패율 실측. 하루 표본이 540판이라 아무것도 바꾸지 않아도 13.4%에서 22.8%까지 움직임. 기대 효과 0.9%p는 이 안에 완전히 묻힘.

기대 효과 0.9%p는 이 변동 폭 안에 완전히 묻힘. 하루치 숫자로 성패를 읽으려 하면 반드시 잘못된 결론이 남. 매일 보는 건 사고 감시용이고, 성과는 누적으로만 판정함.

BigQuery 비용 설계

3시간마다 전체 구간을 다시 스캔하면 회당 3.91GB, 하루 5회로 19.5GB가 나감. 그래서 일별 원시 카운트를 로컬에 누적하고 지표는 합산으로 계산하는 구조로 짰음.

방식회당 스캔하루 5회
매번 전체 재스캔3.91 GB19.5 GB
증분 캐시 (적용)144 MB0.72 GB
  • 확정된 과거 날짜는 두 번 조회하지 않음 — 캐시에 있으면 건너뜀
  • 매번 다시 읽는 건 진행 중인 오늘 파티션 하나뿐 — log_date in (...)로 파티션 프루닝
  • 비율이 아니라 카운트를 저장 — 합산이 가능해야 누적 구간을 자유롭게 잡을 수 있음
  • 판 길이 중앙값은 히스토그램 버킷 보간으로 구함 — 일별 값을 합산할 수 없기 때문임. ±2초 오차가 있어 가드레일(88~108초) 판정용으로만 씀
  • 캐시를 지우고 --reset으로 돌리면 전 구간을 한 번 백필함 (3.91GB 1회)

게이트 판정도 자동임. 가드레일 표는 원값(사고 감시용)이지만, 그 아래 표준화 지표 블록은 밴드 층화를 거친 값이고 95% 신뢰구간으로 유의성까지 판정함. D+3 · D+7 게이트는 이 값을 근거로 자동 평가됨.

아래 층화 판정 쿼리는 손으로 교차 확인하거나 밴드별 원값을 뜯어볼 때 쓰면 됨.

일일 점검 쿼리

매일 이 하나만 돌리면 A그룹 사고 감시가 전부 커버됨. 층화 판정 쿼리는 handoff-sh-rescue-monitoring.html 참조.

with g as (
  select
    case when log_time >= "2026-08-01 09:00:00" then "후" else "전" end arm,
    event, json_value(data,"$.difficulty_tier") tier,
    json_value(data,"$.result")="clear" ok,
    safe_cast(json_value(data,"$.play_time") as int64) pt,
    safe_cast(json_value(data,"$.remaining_card_count") as int64) rc,
    log_date, player_id
  from `game-log-359704.raw.solitaire_city_journey`
  where log_date between "2026-07-14" and current_date()
    and event in ("2100_GAMEPLAY_START","2300_GAMEPLAY_FINISH")
    and is_dev is distinct from true and player_id > 0
)
select arm,
  round(100*countif(event="2300_GAMEPLAY_FINISH" and tier!="20001")
        /nullif(countif(event="2100_GAMEPLAY_START" and tier!="20001"),0),1)          완료율,
  round(100*countif(event="2300_GAMEPLAY_FINISH" and tier="20002")
        /nullif(countif(event="2300_GAMEPLAY_FINISH" and tier!="20001"),0),1)         믹스_normal,
  round(100*countif(event="2300_GAMEPLAY_FINISH" and tier="20003")
        /nullif(countif(event="2300_GAMEPLAY_FINISH" and tier!="20001"),0),1)         믹스_hard,
  round(100*countif(event="2300_GAMEPLAY_FINISH" and tier="20004")
        /nullif(countif(event="2300_GAMEPLAY_FINISH" and tier!="20001"),0),1)         믹스_sh,
  round(100*countif(event="2300_GAMEPLAY_FINISH" and tier="20004" and not ok)
        /nullif(countif(event="2300_GAMEPLAY_FINISH" and tier="20004"),0),1)          sh_실패율,
  round(100*countif(event="2300_GAMEPLAY_FINISH" and tier="20003" and not ok)
        /nullif(countif(event="2300_GAMEPLAY_FINISH" and tier="20003"),0),1)          hard_실패율,
  round(avg(if(event="2300_GAMEPLAY_FINISH" and tier="20004" and not ok, rc, null)),1) sh_잔여,
  approx_quantiles(if(event="2300_GAMEPLAY_FINISH" and tier="20004", pt, null),2)[offset(1)] sh_판길이,
  round(countif(event="2300_GAMEPLAY_FINISH")
        /count(distinct concat(cast(log_date as string),"-",cast(player_id as string))),2) 유저일당_판수
from g group by arm order by arm desc

이 쿼리의 sh_실패율·sh_잔여는 원값이라 층화가 안 돼 있음. 사고 감시(13% 미만 · 2.0배)에는 써도 되지만, 성과 판정에는 쓰면 안 됨.

층화 판정 쿼리

with g as (
  select
    case when log_time >= "2026-08-01 09:00:00" then "후" else "전" end arm,
    case when logincount_total <= 3  then "1_로그인1~3"
         when logincount_total <= 10 then "2_4~10"
         when logincount_total <= 30 then "3_11~30"
         else                              "4_31+"  end                 band,
    json_value(data,"$.difficulty_tier") tier,
    json_value(data,"$.result")="clear"  ok,
    safe_cast(json_value(data,"$.remaining_card_count") as int64) rc,
    safe_cast(json_value(data,"$.play_time") as int64)            pt
  from `game-log-359704.raw.solitaire_city_journey`
  where log_date between "2026-07-14" and current_date()
    and event="2300_GAMEPLAY_FINISH"
    and json_value(data,"$.difficulty_tier")="20004"
    and is_dev is distinct from true and player_id > 0
),
cell as (
  select arm, band, count(*) n,
    countif(not ok)/count(*)            fail,
    avg(if(not ok, rc, null))           remain
  from g group by arm, band
),
w as (   -- 패치 전 밴드 비중을 가중치로 고정
  select band, n/sum(n) over () wt from cell where arm="전"
)
select c.arm,
  round(100*sum(c.fail   * w.wt), 2) fail_std,   -- 표준화 실패율
  round(     sum(c.remain* w.wt), 2) remain_std, -- 표준화 잔여
  sum(c.n) n
from cell c join w using (band)
group by c.arm order by c.arm desc

표준화 실패율만 보면 됨. 밴드별 실패율을 패치 전 비중으로 다시 섞은 값이라, SPEC-029가 구성을 바꿔도 값이 흔들리지 않음. 밴드별 원값도 같이 남겨 이상 밴드가 있는지 확인할 것.
