P1 · UX 개선 · 최우선
튜토리얼 강화
첫 터치 → 첫 카드 매칭 구간 이탈률 감소 목적 · 이탈 -24.6% 구간 직접 대응
문제
튜토리얼 팝업 노출(6초) 직후 10초 구간에서
전체 유저의 24.57%가 이탈. 팝업 텍스트가 길거나
첫 인터랙션 유도가 명확하지 않은 것으로 추정
구현 방향
· 힌트 재생 속도 상향 — 기존 힌트 애니메이션 재생 속도 빠르게 조정,
  유저가 기다리지 않고 바로 인터랙션 가능하도록
· 인덱스 애니메이션 추가 — 1번·2번 튜토리얼 모두 진행 단계 인디케이터(인덱스) 추가
· 2번 튜토리얼 덱 설명 — 덱 설명 화면에도 인덱스 적용 (1번 튜토리얼 강화에 포함)
· 첫 카드 터치 → 카드 매칭 구간 조작 흐름 명확화
목표 지표
≤15%
TUTO_INGAME_INTRO → PLAYTIME_10S 이탈률 (현재 24.6%)
관련 이벤트
2110_TUTO_INGAME_INTRO 팝업 노출
9990_PLAY_FIRST_TOUCH 첫 카드 터치
2150_GAMEPLAY_NRU_CARD_MATCH 첫 매칭
2141_TUTO_STEP_COMPLETE 안내 팝업 닫기 (유저 터치)
P2 · 버그 조사 · 추가 항목
10초 미만 로딩 비정상 유저 원인 파악 및 수정
LOAD_COMPLETE 이후 10초 내 이탈하는 비정상 코호트 특정 · -12.1% 이탈 구간 원인 규명
현상
LOAD_COMPLETE(avg 3.68s) 이후 TUTO_INGAME_INTRO까지
전체 유저의 12.1%가 이탈. 로딩은 완료됐지만
10초 내에 세션이 종료되는 유저군 존재.
정상 플로우라면 이 구간 이탈이 발생하면 안 됨
조사 방향
· 크래시 여부 — LOAD_COMPLETE 직후 앱 강제 종료 로그 확인
· 씬 전환 오류 — 로딩 완료 후 게임판 씬 마운트 실패 케이스
· 네트워크 타임아웃 — 에셋 추가 다운로드 중 끊김
· 기기 스펙 이슈 — 저사양 기기에서 렌더링 지연 후 이탈
· 중복 세션 — 다른 기기 동시 접속으로 세션 강제 종료
수정 방향
원인 파악 후 대응 결정.
크래시 → 스택트레이스 기반 핫픽스
씬 오류 → 씬 초기화 로직 재검토
네트워크 → 재시도 로직 또는 타임아웃 완화
기기 스펙 → 저사양 렌더링 최적화 또는 품질 단계 축소

P3 · UX 개선
토스 로그인 유도 팝업 NRU 미노출
신규 유저 온보딩 중 방해 요소 제거 · 로그인 → 게임 시작 구간 이탈 -7.6% 부분 대응
문제
NRU가 처음 게임에 진입하는 시점에
토스 로그인 유도 팝업이 노출되면
온보딩 흐름이 끊기고 이탈 유발.
게임 경험 전에 계정 전환 유도는
NRU 관점에서 맥락 없는 요청
개선 방향
· NRU 세션(첫 로그인 기준) 동안
  토스 로그인 유도 팝업 미노출 처리
· 노출 조건 분기: isNRU = true이면 skip
· 팝업 노출 시점을 첫 판 클리어 이후로 이동
  (GAMEPLAY_FINISH 이후가 적절)
조건 정의
NRU 기준: 첫 세션 한정
(INTRO_LOGIN 첫 발생 기준)

미노출 범위:
로그인 ~ 첫 판 클리어 전까지

재노출 허용:
2회차 세션부터 정상 노출

P4 · 데이터 수집
1번 튜토리얼 유저 터치 트래킹 로그 추가
유저가 어디서 길을 잃는지 확인 목적 · 튜토리얼 개선의 데이터 근거 확보
목적
현재 퍼널 로그만으로는 튜토리얼 이탈이
어느 단계에서 발생하는지 특정 불가.
터치 위치·타이밍 트래킹으로 이탈 원인
정밀 분석 가능하게 함
로그 스펙
· 대상: 1번 튜토리얼 진입 유저 한정
· 트리거: 화면 터치 이벤트 발생 시
· 수집 항목: 터치 좌표(x,y), 튜토리얼 단계,
  경과 시간(초), 유효터치 여부
분석 활용
· 힌트 영역 밖 터치 → UX 혼선 지점 파악
· 반복 터치 → 조작 방법 모름 지점 파악
· 터치 없이 이탈 → 팝업 읽다 이탈 파악
· P1 튜토리얼 강화 작업의 before/after 측정
주의사항
· 1번 튜토리얼 한정 (전체 로깅 시 과도한 이벤트)
· 개인정보 미포함, 좌표만 수집
· 데이터 볼륨 고려 샘플링 비율 설정 권장
· 튜토리얼 개선 완료 후 수집 종료 가능
P5 · 데이터 정합성
PLAYTIME 중복 로깅 제거
동일 이벤트가 nth=1, nth=2로 중복 기록돼 퍼널 수치 왜곡 · 데이터 신뢰도 직결
현상
1-1110_PLAYTIME_10S 160명 (55.36%)
2-1110_PLAYTIME_10S 158명 (54.67%)

동일 유저의 10초 플레이 이벤트가
nth=1, nth=2로 2회 기록됨.
30초, 60초 구간도 동일 패턴 확인
영향
· 퍼널 집계 시 중복 row로 유저수 오계산
· nth=2 행을 별도 이벤트로 오해할 가능성
· avg_sec 평균값 왜곡 (1회 vs 2회 평균)
· BigQuery 쿼리 시 DISTINCT 처리 강제 필요
해결 방향
· 클라이언트: PLAYTIME_10S/30S/60S는
  세션당 1회만 발송 (중복 발송 로직 제거)
· 또는 서버: nth > 1 행 필터링 후 저장
· 대상: 10s / 30s / 60s 전체
적용 대상 이벤트
1110_PLAYTIME_10S
1120_PLAYTIME_30S
1130_PLAYTIME_60S
