Vintage Lane — SRS 요구사항 명세서 + 콘텐츠 물량

전략문서 Part 4(출시 스펙)를 개발 착수 가능한 Part A 기능/비기능 요구사항(FR·NFR)과 Part B 콘텐츠 물량 산정(아트·스토리·오디오·문자열)으로 상세화한다. 모든 수치는 Gossip Harbor APK 리버싱(Lua 소스·config·밸런스 시트)에서 도출한 실측값을 1차 기준으로 삼고, 시니어·논타이머 컨셉에 맞춰 조정했다(§8 캘리브레이션 참조). 요구사항 우선순위: P0=출시필수 / P1=Fast-follow / P2=Later.

1

목적 · 범위 · 정의

1.1 목적

Vintage Lane v1.0(FB Instant Games, 40–65세 북미 여성(시니어 친화) 타겟 머지-2)의 소프트웨어 요구사항을 정의한다. 개발·QA·기획의 단일 기준 문서.

1.2 범위

v1.0 출시 범위(코어 머지 루프·스토리/복원·논타이머·최소 라이브옵스·수익화·40–65세 시니어 친화 UX)를 다룬다. 소셜/길드·분기 스토리·다국어 등은 P2로 범위 외.

1.3 용어 정의

용어정의
체인(Chain)같은 계열 아이템의 레벨 사슬(레벨1→N). 두 동일 아이템 병합 시 +1레벨.
생성기(Generator)탭하면 낮은 레벨 아이템을 생산하는 보드 오브젝트.
오더(Order)손님 주문. 요구 아이템 제출 시 코인/보상.
코인/젬코인=소프트(단일목적) · 젬=하드(다목적, 구매 가능).
논타이머시간압박(에너지 고갈·타이머 스킵 강요)을 최소화한 페이싱. 무에너지 또는 소프트에너지.
이벤트 하네스이벤트가 코어 루프를 재사용하도록 하는 구조 + 리모트 config로 클라 업데이트 없이 이벤트 추가.
2

전체 설명

제품 관점

HTML5 인스턴트 게임. 서버는 세이브·리모트config·이벤트·IAP 검증 담당. 코어 로직은 플랫폼 독립(멀티플랫폼 포팅 여지).

운영 환경

Facebook/Instagram Instant Games(모바일 웹뷰). 구세대 단말·저대역 네트워크 고려. ≤200MB.

제약·가정

3.0

기능 요구사항 읽는 법 — ID 규칙 · 데이터 시트 연동

§3의 모든 기능 요구사항은 동일한 형식을 따른다. 각 요구사항이 어떤 밸런스 시트 탭의 어떤 컬럼을 참조해 구현되는지를 함께 명시하므로, 개발자는 이 문서의 FR → 시트 탭 → JSON → 서버 config 순서로 값을 그대로 끌어다 쓸 수 있다.

요구사항 ID 명명 규칙

FR-<도메인>-<일련번호>
  • FR = Functional Requirement(기능 요구사항). 비기능은 NFR-<범주>-NN.
  • <도메인> = 기능 영역 약어. 본 문서 §3의 소절과 1:1 대응 — BOARD(보드)·GEN(생성기)·ORDER(오더)·ECON(이코노미)·STORY(스토리·복원)·PROG(진행·레벨)·PACE(논타이머)·ONB(온보딩)·SAVE(세이브)·MON(수익화)·LIVE(라이브옵스)·A11Y(접근성)·BI(계측).
  • <일련번호> = 도메인 내 2자리 순번(01, 02…). 번호 자체에 우선순위 의미는 없으며, 우선순위는 별도 P0/P1/P2 컬럼으로 표기.
  • 이 ID는 §7 추적성 표에서 전략문서(PRD)와, 하단 트래커의 개발 태스크와 상호 참조된다.
