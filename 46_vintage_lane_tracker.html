⚙️ 병행 전략 요약 (오케스트레이터)

  • Phase 0은 전부 병행 — 데이터/규칙/소스는 이미 완료. 남은 BI 택소노미·에셋 추출은 서로 독립이라 동시 착수.
  • Phase 1의 3트랙(아트·개발·라이브옵스)은 완전 병행. 개발 프로토는 P0 데이터로 즉시 가능, 아트는 에셋추출(P0)을 레퍼런스로 디자인시스템 먼저.
  • 서버 백엔드는 P0부터 병행 착수(설계·계약) 하되, 클라 통합은 P2. 개발↔서버 API 계약을 조기 확정해 블로킹 방지.
  • 임계 경로(Critical Path): 데이터✅ → 코어루프 프로토(P1개발) → 보드/저장 시스템(P2) → 이벤트/라이브옵스(P3). 아트·서버는 이 경로에 병렬 공급.
  • 차단 리스크: 서버 전용값(에너지 라이브·이벤트 스케줄·패스 실제값)은 APK에 없음 → 서버팀 or 라이브 관찰로만 확보. 코어 MVP엔 로컬 기본값으로 진행.
