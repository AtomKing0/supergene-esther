문제 — 친구 탭까지 왔는데 할 것이 없음

리더보드 친구 탭은 This Week와 All-Time이 좌우로 함께 보임. 그런데 버튼이 붙어 있는 쪽은 This Week뿐이고, 그마저도 선물 버튼 하나임. 노출 조건이 isWeekly && isFriends && !isMine에 더해 선물 쿨다운과 공유 가능 여부까지 걸려 있어 대부분 꺼져 있음.

All-Time 리스트는 버튼이 아예 없음. 순위와 별 개수만 보고 나가는 화면임.

2026-07-31 ~ 08-06 실측. 친구 탭까지 온 198명이 만든 행동이 선물 13건 · 전환 6건임.

바이럴리티가 EQR v4에서 상위 20% 진입 가산 항목이 됐고, 그게 우리 최대 공백임. 친구 메시지 비중이 0.07%로 벤치 14.7~17.9%에 한참 못 미침. 3필러(리텐션 · WAU@14 · 평점)보다 빠르게 움직일 수 있는 기능 레버라, 8월 중순 소셜 확대 블록의 첫 타자로 적합함.

고칠 부분 — All-Time 리스트의 빈 오른쪽

This Week의 선물 버튼은 그대로 둠. All-Time 리스트 각 행의 오른쪽 빈 자리에 Play 버튼을 놓음. 선물과 달리 쿨다운이 없어 상시 노출됨.

선물 버튼과 목적이 다름. 선물은 전환 후 메시지를 보내고 끝이지만, Play는 전환 후 판을 시작함. 같은 전환 자산을 쓰되 성공 콜백이 갈림 — 선물은 sendGiftMessage, Play는 프리레벨 팝업 진입임.

후속 — 이 건과 분리

친구 탭 진입이 리더보드 열람의 13.9%뿐임. Play 버튼은 이미 들어온 사람에게만 닿으므로, 지면 트래픽을 키우는 것은 별도 과제로 남김 — 리더보드 진입 동선, 친구 탭 기본 선택 여부, 친구 초대 지면이 여기에 해당함.

개발 스펙

서버 저장 상태 모델

이 기획은 서버 상태를 새로 만들지 않음. 컨텍스트 생성은 페이스북 SDK가 처리하고, 서버는 기존 친구 관계 갱신만 그대로 씀. 신규 API 없음.

서버 상태전이 조건저장 · 갱신 값
친구 관계 없음초기 상태—
친구 관계 있음updateFriendship 수신friendInfo — 선물 버튼이 이미 쓰는 것과 동일
Play는 updateFriendship을 호출하지 않음. 선물은 보낸 이력을 남겨야 쿨다운이 걸리지만 Play는 쿨다운이 없음. 서버에 남길 것이 없으므로 호출하지 않는 것이 맞음 — 호출하면 선물 쿨다운이 잘못 갱신됨.
