문제 — 접속 직후 입장료에서 막힘

골드가 부족한 것은 총량 문제가 아님. 골드 수지는 획득/소비 1.219배 흑자이고 판당 보상이 입장료의 3.3~5.6배임. 문제는 다 쓰고 나서 다음 판을 못 들어가는 순간이며, 그 순간이 접속 직후에 집중됨.

확정 설계 — Lv 50 미만, 세션 첫 판은 입장료를 차감하지 않음

세션의 첫 게임 시작에서 골드 차감 자체를 건너뜀. 진입 판정은 로그인 이후 마지막 게임 정보 데이터의 유무로 하고, 데이터가 없으면 프리레벨 팝업을 건너뛴 첫 게임 시작 프로세스(튜토리얼 진입과 동일한 형태)로 바로 판에 들어감.

형평성 — 왜 전 구간이 아니라 Lv 50 미만인가

광고 보상은 entry_cost × rv_gold_ratio / 10000으로 계산되며, 이 비율이 레벨을 따라 65% → 30%로 내려감. 고레벨일수록 회복 수단을 의도적으로 억제해둔 설계임. 그런데 무료 입장은 x1 입장료를 전액 면제하므로, 전 구간에 주면 두 수단의 방향이 정반대가 됨.

비용 — 주간 골드 소비 0.39%

입장료 전면 폐지와는 규모가 완전히 다름. 토스 빌드 220 A/B에서 입장료를 폐지했을 때 인당 판수가 46% 감소했으나(골드 소비의 78.9% 소멸), 본 안은 0.39%이며 골드를 벌 목표 자체는 그대로 유지됨.

기대 효과

  • 접속 직후 진입 실패 제거 — 세션 첫 판은 잔고와 무관하게 항상 시작 가능
  • 세션 초반 광고 호출이 줄어듦 — 30초 이내 free_coin 호출 505건 중 상당수가 불필요해짐. 이 구간은 완료율이 29.7%로 실패가 집중되던 곳임
  • 첫 판 도달 속도 상승 — 골드 충전 팝업 → 광고 → 실패 → 상점 동선이 사라지고, 프리레벨 팝업 단계도 함께 빠짐

서버 — 상태 모델

클라 연출과 무관하게 서버가 기억하는 상태는 아래 넷임. 판정 입력은 마지막 게임 정보와 당일 무료 입장 사용 횟수 두 개뿐임.

상태전이 조건저장 · 갱신 값
무료 입장 가능로그인 이후 마지막 게임 정보가 없음 + 레벨 조건 충족 + 당일 사용 < 상한— (판정 결과만 로그인 응답에 실림)
무료 입장 소진무료 입장으로 게임이 시작됨lastGameInfo 기록 · freeEntryUsedCount +1
상한 도달당일 사용 횟수 = session_free_entry_daily_cap당일 리셋 전까지 새 세션에서도 무료 입장 없음
대상 밖레벨 < min_level 또는 레벨 ≥ max_level, 또는 상한 0저장 없음 — 기존 입장료 흐름 그대로
시간 용어 3층. 세션 = 로그인 1회(마지막 게임 정보가 없는 상태로 시작하는 구간) · 무료 입장 1회 = 세션 안에서 소비되는 참여 단위 · 일일 창 = UTC 0시부터 다음 0시까지, 상한 3회가 세어지는 범위. lastGameInfo의 존재 자체가 "이 세션은 이미 무료 입장을 썼거나 유료로 판을 시작했다"는 의미임.

서버 — 처리 흐름

1
로그인 처리에서 마지막 게임 정보 유무 확인

레벨 조건과 당일 사용 횟수를 함께 판정해 무료 입장 가능 여부를 응답에 실어 보냄

2
게임 시작에서 골드 차감을 건너뜀

무료 입장으로 시작된 판은 entry_cost = 0으로 처리. freeEntryUsedCount를 올리고 마지막 게임 정보를 기록함

3
게임 종료에서 x1 보상 기준을 지정

배수 선택 단계를 지나쳤으므로 보상 계산 배수를 1로 고정하는 필드를 게임 종료 처리에 둠
