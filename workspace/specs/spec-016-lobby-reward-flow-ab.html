로비 보상 연출 중 팝업 차단 개선 A/B

판 종료 후 로비 복귀 시 보상 연출이 진행되는 동안 게임 진입이 차단된다. 이벤트 마일스톤 보상 팝업을 강제 노출하는 현재 방식 vs. 레드닷 표시 후 유저 선택으로 확인하는 방식을 A/B 테스트로 검증한다.

문제

판 종료 후 로비로 복귀할 때 보상 획득 연출 + 이벤트 마일스톤 팝업이 순차적으로 표시된다. 이 연출이 진행되는 동안 게임 진입 버튼이 차단되어, 빠르게 다음 판을 시작하고 싶은 유저에게 마찰이 발생한다.

현재 구조 (원인)

  • 연출 목적: UI 변화(재화 증가 등) 시각화 + 이벤트 팝업 순차 노출
  • 실제 데이터(보상)는 서버에서 이미 적용 완료 — 연출은 시각적 피드백
  • 이벤트 팝업이 연출 흐름에 묶여 있어 연출 종료 전까지 팝업 닫기/스킵 불가

핵심 인사이트: 데이터는 이미 반영되어 있으므로 연출을 강제로 다 볼 필요가 없다. 유저가 원할 때 확인할 수 있으면 충분하다.

가설

이벤트 마일스톤 보상 팝업을 강제 노출하는 대신, 이벤트 아이콘에 레드닷을 표시하고 유저가 직접 진입하도록 하면 — 게임 진입 마찰이 줄어 세션당 플레이 횟수가 증가할 것이다.

②
A/B 설계
전체 공유
A — Control (현재)
이벤트 팝업 강제 노출
  • 보상 연출 종료 후 이벤트 마일스톤 팝업 자동 표시
  • 팝업 닫기 전까지 게임 진입 차단
  • 보상 인지율 높음
  • 연속 플레이 흐름 끊김
B — Variant (제안)
레드닷 → 유저 선택 진입
  • 이벤트 마일스톤 달성 시 이벤트 아이콘에 레드닷 표시
  • 팝업 자동 노출 없음 — 게임 즉시 진입 가능
  • 유저가 원할 때 이벤트 아이콘 탭 → 팝업 확인
  • 연속 플레이 흐름 유지

B안 구현 포인트

  • 이벤트 마일스톤 달성 판정: 기존 팝업 트리거 조건 그대로 활용, 팝업 노출만 억제
  • 레드닷 표시: 이벤트 아이콘에 미확인 마일스톤 보상이 있을 때 레드닷 활성화
  • 팝업 진입: 이벤트 아이콘 탭 시 기존 마일스톤 보상 팝업 노출 (기존 UI 재사용)
  • 레드닷 해제: 팝업 진입 후 확인 시 레드닷 제거
