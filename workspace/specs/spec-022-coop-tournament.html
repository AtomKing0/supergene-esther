배경 — 경쟁이 아닌 협력이 만드는 바이럴

Facebook Instant Tournament는 기본적으로 개인 점수 경쟁 구조다. 그러나 플레이어가 서로 경쟁하는 것이 아니라 함께 목표를 달성하는 협력 구조로 전환하면 두 가지 장점이 생긴다.

  • 바이럴 동기 강화: 경쟁은 "내가 이겨야 하므로 혼자" 하려는 경향이 있지만, 협력은 "더 많은 친구를 초대해야 목표를 달성할 수 있다"는 초대 동기를 만든다
  • 긍정적 사회 감정: 함께 성공했을 때의 보상 공유 경험은 게임에 대한 우호적 기억을 남긴다. 재참여율·입소문 지표 개선 기대
  • 기존 코어 루프 유지: Peak Cup(SPEC-021)과 동일하게 유저는 기존 레벨을 플레이하면 된다. 별도 모드 없음
핵심 원칙: FB 토너먼트 API는 소셜 초대 및 공유 레이어로만 활용한다. 협력 스코어 집계와 목표 달성 판정은 자체 서버에서 처리한다. FB API의 payload 필드에 그룹 목표값과 챌린지 ID를 심어 두 시스템을 연결한다.

1-1 협력 메커닉 상세

목표 점수 산정 방식

고정 목표가 아닌 팀 인원 수 × 기준 점수로 자동 산정한다. 인원이 많을수록 목표도 비례 상승하지만, 1인당 기여 부담은 동일하게 유지한다.

팀 인원목표 점수 산식예시 (기준 50,000점)
2인coop_base_goal × 2100,000점
3인coop_base_goal × 3150,000점
4인coop_base_goal × 4200,000점
5인coop_base_goal × 5250,000점
단계 목표(Milestone) 옵션: 초기 출시는 단일 목표 달성 구조로 단순하게 시작한다. 후속 이터레이션에서 중간 마일스톤(25%, 50%, 75% 도달 시 소량 보상)을 추가해 달성 경험을 단계화할 수 있다.

개인 기여 점수 계산

  • 레벨 클리어 1회 = 스타 점수(star_score) × coop_score_multiplier
  • 스타 점수: ★1 = 1,000점 / ★2 = 2,500점 / ★3 = 5,000점 (예시, 실수치는 시트 확정)
  • 기여 점수에는 상한(coop_max_score_per_level)을 두어 어뷰징 방지
  • 리트라이 실패(레벨 클리어 못함)는 점수 기여 없음

1-2 플레이어 경험 흐름

챌린지 생성 (호스트)
로비의 "친구와 도전" 버튼 탭 → 챌린지 생성 화면에서 참가 인원 슬롯(2~5인) 선택 → FBInstant.tournament.createAsync() 호출 → FB 메신저 스레드에 챌린지 카드 자동 공유. 카드에는 목표 점수, 남은 시간, 현재 진행률이 표시됨.
초대 수락 (팀원)
메신저 챌린지 카드의 "참여하기" 탭 → 게임 실행 → FBInstant.tournament.joinAsync(tournamentID) → 서버에 참가 등록. 로비에 그룹 챌린지 배너 즉시 노출. 팀 정원 초과 시 "이미 팀이 가득 찼습니다" 안내.
레벨 플레이 → 점수 기여
기존 레벨 클리어 시 개인 기여 점수가 그룹 풀에 자동 누적. 클리어 완료 연출 후 "+[점수] 팀에 기여!" 피드백 토스트 노출. 로비 챌린지 배너의 진행 바(progress bar)가 실시간 업데이트.
상황 공유 (선택)
로비 챌린지 배너의 "친구에게 응원 요청" 버튼 탭 → FBInstant.tournament.shareTournamentAsync() → 현재 진행률이 담긴 카드를 메신저에 재공유. 팀원 독려 또는 추가 참가 유도에 활용.
목표 달성 또는 시간 초과
달성: 서버에서 목표 도달 감지 → 모든 팀원에게 푸시 알림 발송 + 인게임 팝업 노출 → 팀원 전원 동일 보상 지급. 실패: 24시간 타이머 만료 시 조용히 종료, 팀원에게 결과 요약 알림(소량 위로 골드 지급 여부는 coop_fail_consolation 설정에 따름).
보상 수령
결과 팝업에서 "보상 수령" 탭 시 지급. coop_reward_claim_window_sec 내 미수령 시 자동 지급. 메신저에 달성 결과 카드 자동 공유 (팀원 이름 + 달성 시간 표시).

3-1 Facebook Instant Tournament API 연동

아키텍처 원칙: FB Instant Tournament API는 소셜 발견 & 초대 레이어만 담당한다. 협력 스코어 집계·목표 달성 판정·보상 지급은 자체 서버에서 처리한다. 두 시스템은 tournament.getID()로 반환되는 토너먼트 ID와 payload 필드를 통해 연결된다.

챌린지 생성 흐름

// 호스트가 챌린지 생성 버튼 탭 시
const endTime = Math.floor(Date.now() / 1000) + coopDurationSec; // 현재+24h

const tournament = await FBInstant.tournament.createAsync({
  initialScore: 0,
  config: {
    title: "친구와 함께 도전하세요!",
    image: challengeCardBase64, // 아트팀 제공 카드 이미지
    sortOrder: 'HIGHER_IS_BETTER',
    scoreType:  'NUMERIC',
    endTime:    endTime,
  },
  payload: JSON.stringify({
    type:        'cooperative',
    challengeId: newChallengeId,   // 서버에서 미리 발급한 챌린지 ID
    groupGoal:   groupGoalScore,   // 팀 인원 × coop_base_goal
  }),
});

const fbTournamentId = tournament.getID();
// 서버에 fbTournamentId 등록 → 참가자 조회 시 사용
await serverApi.registerChallenge(newChallengeId, fbTournamentId);

// 메신저에 챌린지 카드 자동 공유
await FBInstant.tournament.shareTournamentAsync({
  score: 0,
  data: { challengeId: newChallengeId },
});

팀원 참가 흐름

// 메신저 카드 탭 → 게임 실행 시 진입점
const entryPointData = FBInstant.getEntryPointData();
if (entryPointData?.challengeId) {
  await FBInstant.tournament.joinAsync(entryPointData.fbTournamentId);
  await serverApi.joinChallenge(entryPointData.challengeId, playerId);
  // 정원 초과 시 서버에서 error: 'CHALLENGE_FULL' 반환 → UI 안내
}

레벨 클리어 시 점수 기여

// game_end 이벤트 처리 (기존 레벨 클리어 파이프라인에 추가)
if (activeChallenges.length > 0 && levelCleared) {
  const contribution = calcContribution(starScore); // star×multiplier, 상한 적용

  // 자체 서버에 기여 점수 누적
  await serverApi.postContribution(challengeId, playerId, contribution);

  // FB 토너먼트에도 개인 누적 점수 업데이트 (리더보드 표시용)
  await FBInstant.tournament.postScoreAsync(myTotalContribution);

  // 서버 응답에 목표 달성 여부 포함 → 달성 시 클라 팝업 트리거
}
주의 — postScoreAsync 호출 빈도: 레벨 클리어마다 매번 호출하면 FB API 레이트 리밋에 걸릴 수 있다. 호출 간격을 최소 10초 이상 두거나 배치 업데이트 방식을 검토. 최악의 경우 FB 점수는 약간의 지연을 허용하고, 실제 협력 집계는 자체 서버만으로 동작하도록 설계.

POST /challenge/join팀원 참가 등록. 정원 초과 시 오류 반환.
POST /challenge/contribute점수 기여 기록. group_total_score 업데이트. 달성 여부 응답에 포함.
GET /challenge/status현재 group_total_score, 팀원 기여 목록, 남은 시간 반환. 클라 폴링용.
POST /challenge/claim보상 수령 처리. 중복 수령 방지 (idempotent).

3-4 엣지 케이스

케이스처리 방법
호스트만 참가, 팀원 미수락 CREATED 상태 유지. coop_duration_sec 내 최소 인원 미충족 시 자동 FAILED 전환. 호스트에게 알림.
팀원이 챌린지 도중 FB 연결 해제 기존 기여 점수는 유지. FB 연결이 끊긴 팀원의 신규 기여는 서버에서 userId 기반으로 계속 집계. (FB API 오류는 자체 서버 로직과 독립)
정원 초과 참가 시도 서버에서 CHALLENGE_FULL 오류 반환. 클라에서 "팀이 가득 찼습니다" 안내. FB joinAsync는 성공해도 서버 참가 등록은 거부.
동시에 여러 챌린지 목표 달성 각 챌린지 독립적으로 처리. 순서 보장 필요 없음. 보상은 챌린지별로 개별 지급.
목표 달성 직후 추가 레벨 클리어 (초과 점수) 달성 후 기여는 집계하지 않음. SUCCESS 상태 전환 즉시 contribute API 잠금.
동일 유저의 중복 보상 수령 시도 claim API idempotent 처리. 서버에서 수령 기록 확인 후 이미 지급된 경우 성공 응답만 반환 (재지급 없음).
FB tournament.postScoreAsync 실패 FB 점수 업데이트는 베스트 에포트(best-effort). 실패해도 자체 서버 집계와 달성 판정은 영향 없음. 클라 에러 로그만 기록.
coop_in_use를 0으로 전환 (운영 중 비활성화) 진행 중인 챌린지는 해당 회차 완료까지 유지. 신규 챌린지 생성만 차단. 강제 중단 없음.
FB Instant Tournament API 제약 사항:
  • 토너먼트는 경쟁 리더보드 구조가 기본이다. 협력 목표 달성 여부는 FB API가 아닌 자체 서버가 판정한다
  • getTournamentsAsync()로 유저가 참가 중인 토너먼트 목록 조회 가능 — 앱 실행 시 활성 챌린지 복원에 활용
  • 토너먼트 ID는 FB 메신저 스레드 컨텍스트와 연결된다 — 같은 스레드의 친구들에게만 공유됨
  • endTime은 생성 시 고정된다. 연장/단축 불가. 서버에서 별도 연장 로직은 FB 토너먼트와 무관하게 처리 가능
