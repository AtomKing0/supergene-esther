Peak Cup — 100인 데일리 경쟁전

하루 3시간, 100명이 같은 시간에 경쟁하는 실시간 랭킹 이벤트. 레벨 클리어 승수로 순위를 다투고, 상위 랭커에게 보상을 지급한다.

배경 — 경쟁이 만드는 세션

현재 게임의 핵심 일일 루프는 레벨 진행 + 메타(도시) 성장이다. 외부 경쟁 요소가 없기 때문에 유저는 "오늘 접속하지 않아도 된다"는 여유를 느낀다. Peak Cup은 하루에 딱 3시간이라는 시간 제약을 통해 그 날 접속을 유도하는 강력한 리텐션 훅을 제공한다.

  • 문제: 경쟁이 없어 일일 접속 긴박감이 낮다. 자연스럽게 세션 빈도가 줄어들 수 있음
  • 기회: Royal Match의 King's Cup처럼, 실시간 100인 풀 내 순위 경쟁은 사회적 비교 심리를 자극해 세션 깊이와 접속 빈도를 동시에 끌어올린다
  • 목적: 하루 1회 정해진 시간대에 100명의 유저를 한 풀에 묶어, 승수(레벨 클리어 횟수)로 순위를 가리는 단기 경쟁전을 운영한다
  • 범위: 서버 풀 구성 + 클라 리더보드 UI + 보상 지급. 기존 레벨 클리어 플로우는 변경 없음
핵심 원칙: 유저는 기존과 똑같이 레벨을 플레이한다. 단지 이벤트 시간 동안 클리어할 때마다 승수가 쌓이고 실시간으로 순위가 반영될 뿐이다. 진입 장벽이 없고, 별도 플레이 모드가 필요 없다. 이것이 Royal Match King's Cup의 핵심이다.

1-1 플레이어 경험 흐름

이벤트 시작 알림 수신
매일 오후 8시, 이벤트 시작 시 푸시 알림 발송. 알림 탭 시 게임 실행 → 로비에 Peak Cup 배너/탭 노출. 이벤트 시작 전 로비에 카운트다운 배너 노출 (예: "1시간 후 시작").
풀 배정 & 리더보드 진입
이벤트 시간 내 최초 레벨 클리어 시 서버에서 100인 풀에 자동 배정. 리더보드 버튼 탭 시 현재 순위 화면 진입. 내 현재 순위 + 상위/하위 플레이어 승수 확인 가능.
레벨 플레이 → 승수 적립
기존과 동일하게 레벨을 클리어하면 승수가 1 증가. 클리어 완료 연출 후 "Peak Cup +1" 피드백 토스트 노출. 실시간으로 리더보드 순위 반영 (폴링 또는 실시간 업데이트).
이벤트 종료 (오후 11시)
카운트다운이 0에 도달하면 순위 확정. 게임 플레이 중이라면 현재 판 종료 후 결과 반영 (진행 중인 판은 카운트하지 않음). 최종 리더보드 화면으로 자동 전환.
결과 & 보상 수령
최종 순위와 보상 내역이 담긴 결과 팝업 노출. "보상 수령" 탭 시 인벤토리에 지급. 이벤트 종료 후 24시간까지 보상 수령 대기 상태 유지. 다음 날 오후 8시에 새 풀 구성.

전체 방향성

  • 긴장감과 열기를 표현하는 색상 — 골드, 진한 주황, 딥 네이비 계열의 대비
  • 타이머 카운트다운이 메인 시각 요소 — 숫자가 크고 선명하게, 시간이 줄수록 색상이 더 강렬해지는 느낌
  • 리더보드는 깔끔하고 읽기 쉽게 — 내 순위는 항상 화면 내 고정 표시, 다른 플레이어들과 구분되는 강조
  • 1위 뱃지는 왕관 모티프, 2·3위는 메달 모티프 — 기존 게임의 시각 언어와 통일
  • 승수가 오를 때마다 경쾌한 +1 피드백 — 과하지 않되 인지 가능한 수준

와이어프레임 1 — 로비 진입점 (이벤트 배너)

로비 화면 — 이벤트 운영 시간 동안 Peak Cup 배너가 로비 상단에 고정 노출. 카운트다운 실시간 표시.

와이어프레임 2 — 실시간 리더보드 화면

리더보드 화면 — TOP3 포디엄, 순위 리스트, 내 순위 고정 표시, 현재 구간 보상 미리보기. 플레이 버튼으로 바로 레벨 진입 가능.

와이어프레임 3 — 이벤트 종료 결과 화면

결과 팝업 — 최종 순위, 보상 내역, 내일 안내 표시. 보상은 24시간 내 언제든 수령 가능.

3-2 서버 로직

풀 구성 (매칭)

  • 이벤트 시작 시각 (peak_cup_open_hour_utc) 기준으로 서버에서 당일 활성 유저를 100명씩 풀에 묶음
  • 풀 배정 기준: 이벤트 시간 내 최초 레벨 클리어 시점에 미배정 상태면 빈 풀에 할당. 풀이 꽉 찼으면 새 풀 생성
  • peak_cup_min_real_players개 미달인 풀은 10분 추가 대기 후 봇으로 나머지 채움
  • 풀은 이벤트 종료 시까지 고정. 재배정 없음

승수 집계

  • 트리거: 레벨 클리어 API 성공 응답 수신 시 (game_end 이벤트, 클리어 판정)
  • 이벤트 활성 시간 내 클리어만 카운트. 이벤트 종료 시각 이후에 응답이 도착한 판은 카운트 제외
  • 보스 레벨, 튜토리얼 레벨 포함 여부: 포함 (모든 레벨 클리어 = 1승)
  • 동점 처리: 서버 수신 시각 기준으로 먼저 도달한 유저가 상위 순위

봇 동작 규칙

  • 봇 닉네임: 봇 닉네임 풀에서 랜덤 선택. 실 유저와 외관상 구분 불가
  • 봇 승수 증가: 이벤트 시간 내 무작위 간격으로 승수 증가 이벤트 발생. 상한은 [bot_max_wins]
  • 봇은 항상 실 유저보다 낮은 승수 대역에 집중 배치 → 실 유저가 1위권에 도달하기 어렵지 않게
  • 봇 상위 순위 점령 방지: 봇 최대 승수는 상위 10% 실 유저 예상 승수보다 낮게 설정 (런칭 후 데이터 기반 조정)

보상 지급

  • 이벤트 종료 시 서버에서 최종 순위 확정 → 구간 보상 결정 → 보상 수령 대기 상태로 전환
  • 유저가 보상 수령 버튼을 탭할 때 실제 지급 (클라 요청 → 서버 처리)
  • peak_cup_reward_claim_window_sec 내 미수령 시 자동 지급 (다음 로그인 시)
  • 봇은 보상 지급 대상에서 제외

3-3 엣지 케이스

케이스처리 방법
이벤트 시간 내 게임 플레이 중 종료 시각 도달 현재 진행 중인 판은 승수 카운트 안 함. 서버는 종료 시각 이후 수신된 game_end 이벤트를 무시.
네트워크 단절로 game_end 지연 수신 서버 수신 시각 기준으로 판단. 클리어 시각이 아닌 서버 수신 시각이 이벤트 종료 시각 이전인 경우만 카운트 인정. 별도 허용 시간(grace period)은 두지 않음.
풀에 실 유저 0명 (서비스 초기) 풀 생성하지 않음. 이벤트 화면 자체를 노출하지 않거나 "준비 중" 상태 표시.
동일 유저가 여러 기기에서 동시 접속 같은 유저 ID로 처리. 기기 중 어느 쪽에서 클리어해도 동일 카운트. 풀 배정은 유저 ID 기준 1개.
이벤트 도중 peak_cup_in_use를 0으로 전환 진행 중인 이벤트는 해당 회차를 마무리하고 다음 회차부터 미노출. 강제 중단 금지.
보상 지급 실패 (서버 오류) 재시도 큐에 등록. 수령 윈도우 내 재시도 최대 3회. 윈도우 만료 후에도 미지급 시 CS 수동 처리 플래그 등록.
어뷰징 — 비정상 승수 (치트) 기존 gold_max_limit과 동일한 어뷰징 감지 파이프라인 적용. 이벤트 승수에도 상한([peak_cup_win_cap]) 설정. 상한 초과 시 해당 회차 참가 무효 처리.
참고 — 기존 상수 연계: 클리어 판정 기준은 기존 game_end 이벤트와 동일. gold_max_limit(10071), is_album_collection_open(10061) 등 기존 const 값에 영향을 주거나 받지 않는다. Peak Cup은 기존 경제 흐름과 완전히 독립된 레이어로 동작.
