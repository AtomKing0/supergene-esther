## 0. 한 장 요약

`difficulty_tier` 시트 **20004(Super Hard) 행의 셀 3개만** 변경함. 클라이언트 코드 변경 없음, 재배포 불필요, 맵 수정 없음.

| 컬럼 | As-Is | To-Be | 무엇인가 |
|---|---|---|---|
| `deck_help_rate` | 625 (6.25%) | **2200 (22%)** | 덱에서 뽑는 카드가 필드와 안 맞으면 매칭되는 값으로 바꿔 내주는 확률 |
| `field_help_rate` | 375 (3.75%) | **1320 (13.2%)** | 덮여 있던 카드가 뒤집힐 때 기준 카드 ±1로 보정하는 확률 |
| `pity_trigger_count` | 99 (도달 불가) | **10** | 위 두 확률이 연속으로 빗나간 횟수가 이 값에 닿으면 확률 무시하고 강제 구제 |

확률 분모는 10000임. **다른 티어 행·같은 행의 다른 컬럼은 손대지 않음.**

**티어 순서** — 세 컬럼 모두 방향이 유지됨. 덱 2200 < Hard 3000 · 필드 1320 < Hard 2450 · pity 10 > Hard 8. 즉 Super Hard는 평상시 도움이 가장 적고, 안전장치는 가장 늦게 걸림.

## 2. QA 체크리스트

**사전 조건** — Super Hard 판 진입이 필요함. 유저 점수 901~1400 구간에서 배정되므로, 테스트 계정 점수를 맞추거나 `dynamic_level`로 강제 배정해서 확인할 것.

**대상 스테이지** — CC_0332 · CC_0384 · CC_0383 (라이브 포기율 상위 3개) · CC_0333

| # | 케이스 | 기대 결과 | 우선 |
|---|---|---|---|
| 2-1 | Super Hard 판을 10회 이상 반복 플레이 | 막혔을 때 매칭 카드가 이전보다 자주 나옴. **판이 늘어지는 느낌은 없어야 함** | 🔴 |
| 2-2 | 강제 구제 발동 빈도 | 시뮬 기준 판당 0.20회 · 4천 판 최댓값 2회. **한 판에서 여러 번 연달아 터지면 이상 신호** | 🔴 |
| 2-3 | 판을 새로 시작 | 이전 판에서 쌓인 미매칭 횟수가 **이월되지 않아야 함.** 새 판 첫 드로우부터 강제 구제가 걸리면 버그 | 🔴 |
| 2-4 | 화면 숫자 분포 | 뒤집히는 카드가 **특정 숫자(기준 카드 ±1)로만 쏠리지 않아야 함.** 6·7·8만 깔리는 느낌이면 이상 신호 | 🔴 |
| 2-5 | Hard 판과 번갈아 플레이 | **Hard가 Super Hard보다 쉽게 느껴져야 함.** 역전되면 즉시 보고 | 🟡 |
| 2-6 | Normal 판 플레이 | 변경 없음 — 체감 차이가 있으면 다른 티어 행이 잘못 건드려진 것 | 🟡 |
| 2-7 | 튜토리얼 진행 | 변경 없음. 튜토리얼은 필드 보정이 강제로 꺼져 있음 | ⚪ |
| 2-8 | 부스터 사용 판 | 와일드·불꽃놀이 사용 시에도 구제 로직이 정상 동작 | ⚪ |
| 2-9 | 네트워크 끊고 시트 로드 실패 유도 | **난이도가 급격히 쉬워지면 보고.** 시트 조회 실패 시 덱 도움률 폴백이 100%임 (아래 3-2 참조) | 🟡 |

## 3. 개발 확인 사항

| # | 항목 | 상태 |
|---|---|---|
| 3-1 | 판 단위 초기화 | **코드로 확인 완료.** `new StageViewModel`이 `initGame()` 한 곳에서만 호출돼 판마다 새 인스턴스가 생성됨 → 카운터 이월 없음. QA 2-3으로 재확인 |
| 3-2 | 폴백 방향 불일치 | `getDeckHelpRate()`는 시트 조회 실패 시 **10000(100%)**, `getFieldHelpRate()`는 **0**을 반환함. 방향이 반대라 시트 로드가 깨지면 난이도가 급격히 쉬워짐. **이번 변경과 별개 사안이나 인지 필요** |
| 3-3 | 카운터 공유 | `_pityFailCount` 하나를 덱·필드 보정이 공유함. 어느 경로든 도움이 나가면 0으로 초기화됨 |
| 3-4 | 티어 매칭 | `DifficultyTier.getByTier()`는 `tier_id`로 조회함. Super Hard = `tier_id 4` = 시트 20004 행 |

## 4. 배포 후 관측 (7일)

| 지표 | 산식 | 합격 기준 |
|---|---|---|
| Super Hard 실패율 | tier 20004의 `result` ≠ clear 비율 | **16% 내외** · 13% 미만이면 과보정 |
| Hard 대비 실패율 배수 | SH 실패율 ÷ Hard 실패율 | **2.0배 이상 유지** |
| 고포기 스테이지 | CC_0332·0383·0384 합산 실패율 | 3%p 이상 하락 · **스테이지별 편차 확인** |
| 실패 시 평균 잔여 | 2300의 `remaining_card_count` 평균 | 12.4장 → 10장 내외 |
| 부스터 사용률 | `booster_used` 비어있지 않은 비율 | 77% 대비 하락이면 정상 |
| Super Hard 판 길이 | 2300의 `play_time` 중앙값 | 98초 대비 크게 변하지 않아야 함 |

**롤백 트리거** — Hard 대비 배수가 2.0배 미만이거나, Super Hard 실패율이 13% 미만으로 떨어지면 `1800 / 1080 / 10`으로 한 단계 하향.

**스테이지별 편차 주의** — CC_0332·CC_0384는 덱이 필드 대비 0.25로 Super Hard 중 가장 빠듯함. 시뮬레이션상 이 두 맵은 구제값을 올려도 개선폭이 작게 나옴. 개선이 세 스테이지에 고르게 나타나지 않으면 맵 구조 문제이므로 구제값을 더 올리지 말고 **맵 재설계 트랙으로 분리**할 것.
