# SCJ 인터랙티브 간트 플래너 — 제작 프롬프트

SCJ(Solitaire City Journey) 런칭 일정을 관리할 수 있는 인터랙티브 간트 플래너를 단일 HTML 파일로 만들어주세요.

## 핵심 컨셉

단순 표시용 문서가 아니라, 태스크를 수정하면 일정이 자동 재계산되고 직군별 리소스 충돌을 감지하는 가벼운 간트 차트입니다.

---

## 1. 데이터 모델

각 태스크의 속성:

- `id`: 고유 식별자 (문자열)
- `name`: 태스크명 (예: "Toss 빌드 제작")
- `platform`: `"FB"` | `"Toss"` | `"IG"` | `"CG"` | `"공통"`
- `roles`: 담당 직군 배열. 직군 단위로 구분 (예: `["클라", "서버"]`, `["클라"]`, `["QA"]`, `["기획"]`)
- `durationDays`: 소요 영업일수 (숫자, 수정 가능)
- `dependencies`: 선행 태스크 id 배열
- `startDate`: 자동 계산 (모든 선행 태스크 중 가장 늦게 끝나는 날의 다음 영업일)
- `endDate`: 자동 계산 (startDate로부터 durationDays 영업일 후, 주말 제외)
- `type`: `"task"` | `"milestone"`
- `notes`: 메모 (선택)

### 직군 Capacity (중요)

직군별로 동시에 처리 가능한 인원수를 설정할 수 있어야 합니다:

- 기획: 1
- 클라: 2 (클라1, 클라2로 나뉘어 있기 때문)
- 서버: 1
- QA: 1

기본값은 위와 같지만 UI에서 수정 가능해야 함.

## 3. 필수 기능

### A. 간트 차트 뷰 (메인)

- 가로축: 날짜. 주말(토/일)은 회색 음영
- 세로축: 태스크 목록
- 각 bar는 플랫폼별 색상
- 마일스톤은 다이아몬드(◆)로 표시 (소요일 0)
- 오늘 날짜는 수직 붉은 점선
- bar에 태스크명과 담당 직군이 함께 표시

### B. 인라인 편집 (실시간 재계산)

- 태스크명, 소요일수, 직군을 클릭해 즉시 편집
- 소요일수 변경 시 해당 태스크 및 모든 후행 의존 태스크 자동 재계산 (자동 푸시)
- 직군은 다중 선택 드롭다운: 기획 / 클라 / 서버 / QA
- 수정 즉시 간트 차트, 충돌 경고, 요약 대시보드가 함께 갱신

### C. 플랫폼 필터

- 상단 탭: `[전체]` `[FB]` `[Toss]` `[IG]` `[CG]`
- 선택한 플랫폼 태스크만 간트에 표시
- "전체" 뷰에서도 플랫폼별 색상으로 구분

### D. 리소스 충돌 검증 (핵심)

**충돌 정의:**

- 어떤 날짜에 특정 직군이 배정된 태스크 수 > 해당 직군의 capacity
- 예: 클라 capacity=2인데 4/22에 클라가 배정된 태스크가 3개라면 충돌

**표시 방식:**

- 충돌 태스크 bar에 붉은 테두리
- 상단 요약에 "⚠ 리소스 충돌 N건"
- 클릭 시 상세 패널: "4/22-24: 클라 3개 배정 (Toss 빌드, FB 업데이트, XXX) → capacity 2 초과"

### E. 직군 중심 뷰 (토글)

- 뷰 전환 버튼: `[태스크 뷰]` ↔ `[직군 뷰]`
- 직군 뷰에서는 세로축이 직군(기획/클라/서버/QA)
- 각 직군의 행에 그 직군이 담당하는 모든 태스크가 시간순으로 쌓여 표시됨
- 유휴 구간(배정된 태스크 없음)과 충돌 구간이 시각적으로 구별
- **주의:** 한 태스크가 여러 직군에 배정된 경우(예: Toss 빌드 = 클라+서버) 해당 태스크는 클라 행과 서버 행에 중복 표시되어야 함

### F. 태스크 CRUD

- "+ 새 태스크" 버튼
- 각 태스크 행에 삭제 버튼 (휴지통 아이콘)
- 삭제 시 해당 태스크를 선행으로 가진 태스크가 있으면 "이 태스크를 선행으로 가진 태스크 N개가 있습니다. 삭제하면 해당 태스크들의 시작일이 영향을 받습니다." 확인 대화상자
- 의존성은 각 태스크 편집 시 드롭다운으로 선행 태스크 선택/해제 (다중 선택)

### G. 직군 Capacity 설정

- 상단 설정 영역: 각 직군의 capacity를 숫자 입력으로 조정
- 변경 시 충돌 재계산 즉시 반영

### H. 요약 대시보드 (상단 고정)

- 전체 프로젝트 기간: `[최초 시작일]` → `[최종 종료일]` (총 N영업일)
- 주요 마일스톤: Toss 리뷰 제출, Toss 런칭의 자동 계산된 날짜
- 리소스 충돌: N건 (있으면 붉게)
- 플랫폼별 마지막 완료일

### I. 초기화

- "초기 데이터로 리셋" 버튼. 확인 후 초기 상태로 복원

## 4. 기술 제약

- 단일 HTML 파일 (CSS/JS 포함, 외부 파일 없음)
- 외부 라이브러리는 CDN으로만 사용 (date-fns 정도 허용)
- localStorage, sessionStorage, IndexedDB 일절 금지
- 모든 상태는 JavaScript 메모리에서만 관리 (새로고침하면 초기 데이터로 복원됨 — 이건 의도된 동작)
- 영업일 계산: 주말(토/일)만 제외, 공휴일은 무시

## 6. 자체 검증 체크리스트

제출 전 다음을 코드로 확인해주세요:

1. **[초기 상태]** 간트 차트에 14개 태스크가 모두 보이고, 의존성 순서대로 시간축에 배치되는가?
2. **[자동 푸시]** t2(Toss 빌드)의 소요일을 3→6으로 바꾸면 t4, t5, t6(리뷰 제출), t7, t8(런칭)까지 모두 뒤로 밀리는가?
3. **[충돌 감지]** 4/22-24에 t2(클라,서버)와 t3(클라)이 병렬이면 클라 capacity=2라서 충돌 없음. t3의 직군을 "클라"에서 "클라, 서버"로 바꾸면 서버 capacity=1이 초과되어 t2와 t3에 붉은 테두리가 생기는가?
4. **[플랫폼 필터]** CG 탭 클릭 시 t11, t12, t13, t14만 보이는가?
5. **[직군 뷰]** 직군 뷰로 전환하면 QA 행에 t4, t12, t14가 시간순으로 보이는가?
6. **[태스크 삭제]** t2(Toss 빌드)를 삭제하려 하면 "t4, t5가 이 태스크를 선행으로 가짐" 경고가 뜨는가?
7. **[Capacity 변경]** 클라 capacity를 2→1로 줄이면 기존에 없던 충돌이 새로 감지되는가?
